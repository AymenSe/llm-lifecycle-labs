explicit = true restricts an index so it is only used for packages explicitly mapped to it in [tool.uv.sources] (here, torch). Without it, pytorch-cu126 becomes a general index. uv’s default strategy (first-index) gives indexes declared in pyproject.toml priority over PyPI, so uv would search download.pytorch.org first for every package (numpy, mlflow, pyyaml, …). That index mirrors some common packages, often in older or incomplete versions. The resolution would therefore silently change: older numpy, a different dependency set, or failures for packages that exist there only partially. It would also become slower and less auditable, and less safe because of dependency confusion. Torch would still come from the right index, since the sources mapping pins it; the damage is to everything else.
